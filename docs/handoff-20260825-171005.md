### Task 4 实现要点(src/llama-state-incr.cpp)

- 段文件格式:magic `GGSD` + version(1)+ 段索引 u32 + 前段 hash(32 hex)+ token 数 u32(1024)+ payload 大小 u64 + payload hash(sha256 截断 16 字节,写入后回填)+ model_id 字符串 + kv_params 字符串 + 1024 个 llama_token + KV payload。
- 内容寻址:段 hash = sha256(model_id 长度+model_id、kv_params 长度+kv_params、前段 hash 或 0、1024 tokens),取前 16 字节转 hex。文件名为 `seg_<hash>.bin`,与 session 文件同目录。
- `state_seq_save_incr`:读 session 文件(损坏则新链)→ 计算提示词段 hash 链 → 找 fork 点(段文件不存在或 KV 缓存缺该段)→ 从 fork 点写新段(先写 `.tmp` 再 rename)→ 用 dummy IO 测量 payload 大小 → 最后重写 session 文件(仅当链变化)。返回链段数,`(size_t)-1` 出错。
- `state_seq_load_incr`:读 session → 计算提示词前缀段 hash → 找最长匹配段文件链 → 少于 `min_prefix_tokens` 则返回 0 → `seq_rm` 清序列 → 逐段读(校验 magic/version/索引/模型一致/payload hash),`ggsd_io_read_host` 延迟到析构时把 tensor 数据写回后端 → 失败回滚。返回恢复 token 数。
- `ggsd_io_write_file`(写时哈希)、`ggsd_io_write_dummy`(测大小)、`ggsd_io_read_host`(宿主内存读,析构回写 tensor)。
- C API 包装:`ctx->synchronize()` + try/catch。
- 关键 include:`llama-impl.h`(LLAMA_LOG 宏)、`llama-mmap.h`(llama_file)、`llama-model.h`(`model.hparams`/`model.arch` 完整定义)、`llama-arch.h`(`llm_arch_name`)、`llama-sha256.h`。

## 编辑工具陷阱(重要,防止重蹈覆辙)

本会话多次遇到"编辑吞行"问题:编辑 MATCH 块时,若 REWRITE 未完整重述 MATCH 内容,会吞掉相邻行/结构体头/函数声明,导致"结构体未闭合""函数未声明""类同名"等诡异编译错误。规则:

- 每次编辑后**立即重读该区域**验证结构完整;
- 编译报"XX was not declared / does not name a type / same name as class"先查头文件对应区域是否被误删或重复;
- 单独一行 `-` 或 `»` 标记使用不当会把 MATCH 块整体替换并吞行。
