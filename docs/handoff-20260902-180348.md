关键语义变化(与旧实现/旧 spec 的差异):

1. **restore 不依赖 session 文件**:段 hash 链自认证,直接匹配 `session_path` 所在目录中的 `seg_<hash>.bin` → 任意 session / 任意 slot 保存的前缀都可复用(G2 真正兑现)。
2. **KV 驱逐无害**:已持久化段永久有效;save 只在"文件缺失 + KV 有 cells"时写新段;链长 = 磁盘上最长连续前缀。
3. **报错条件**:显式拒绝(SWA / n_pos_per_embd != 1 / 需写头段但 pos 基址非 0)或 head 段既无文件又写不出(`n_chain == 0`,R3);其余一切部分 KV 场景尽力而为、不报错。

## 已知的设计边界(写进了 spec,勿当 bug)

- SWA cache:显式拒绝(save/load 都是)。
- 多模态:save_incr 服务端拒绝;restore 纯文本 tokenize 与含媒体序列天然不匹配,优雅退化。
- FP 非确定性:段 hash 不含 KV payload,命中即跳写 ⇒ 恢复的 KV 可能来自不同 batch 配置的计算——与现有跨 slot prompt cache 同一假设,已声明。
- 单写者:一个进程 per 保存目录;server 内部由任务队列串行。
- 孤儿段无 GC:non-goal,手动清理。
